# Дашборд интернет-магазина

OpenCart (MariaDB) → синхронизация → PostgreSQL → FastAPI → дашборд на Chart.js (тёмная тема, без React).

## Что показывает
Выручка, заказы и средний чек с дельтой к прошлому периоду (7/30/90 дней), график выручки, топ-5 товаров,
последние заказы, остатки (мало на складе ≤5), кнопка полной синхронизации и автосинхронизация раз в 5 минут.
Отменённые и неуспешные статусы исключены из выручки; Pending учитывается. Даты магазина интерпретируются
в `Europe/Kyiv`, в PostgreSQL хранятся как UTC (`timestamptz`), а календарные дни считаются по Киеву.

## Запуск с нуля
```
docker compose down -v                      # (только если уже запускала раньше: чистим старые тома)
docker compose up -d opencart-db opencart
```
1. Открой http://localhost:8080 и пройди установщик OpenCart:
   хост БД `opencart-db`, порт `3306`, пользователь `opencart`, пароль `opencart_pass`, база `opencart`, префикс `oc_`.
2. Наполни магазин тестовыми данными (скрипт сбрасывает тестовые заказы и каталог OpenCart, поэтому используй его только на демо-базе):
   ```
   pip install -r requirements-seed.txt
   python seed_opencart.py
   ```
3. Подними дашборд: `docker compose up -d --build app` и открой http://localhost:8000

Для демо данные OpenCart и PostgreSQL можно сбросить командой `docker compose down -v`, затем повторить шаги выше.
Миграция схемы PostgreSQL применяется автоматически при старте приложения. После seed приложение синхронизирует
данные само; кнопка «Полная синхронизация» также сверяет удалённые заказы. Инкрементальная синхронизация
обновляет заказы, изменённые с прошлого прохода; полная сверка выполняется не реже раза в сутки.

## Структура
- `app/` — FastAPI (`main.py`), синхронизация (`sync.py`), модели, конфиг через переменные окружения (`.env`)
- `frontend/index.html` — дашборд
- `frontend/vendor/` — локальная копия Chart.js и её MIT-лицензия
- `seed_opencart.py` — тестовые товары и заказы за 90 дней
- `docker-compose.prod.yml` — деплой без тестового OpenCart (подключение к реальной БД магазина через `.env`)

## API
`GET /api/config`, `GET /api/stats?days=30` (or `date_from` + `date_to`),
`GET /api/orders` (filters `status`, `q`, date range, sort, pagination), `GET /api/order-statuses`,
`GET /api/orders/{id}`,
`GET /api/products`, `GET /api/stats/breakdown`, `GET /api/stats/heatmap`,
`GET /api/forecast`, `GET /api/analytics/abc`, `GET /api/export/orders.csv`,
`GET /api/sync/log`, `GET /health`, `POST /api/sync`, `POST /api/simulate`,
`GET /api/events` (SSE), `GET /api/live`.

Прогноз остатков использует среднее количество продаж за последние 30 дней. Выручка по товарам и ABC-анализ
суммируют цены позиций заказа; доставка и налоги из общей суммы заказа в этот разрез не распределяются.

## Telegram-бот
Бот запускается вместе с API и использует long polling. Для включения добавь в локальный `.env`:
`TELEGRAM_BOT_TOKEN` от BotFather и `TELEGRAM_ALLOWED_CHAT_IDS` со своим числовым chat_id.
Можно перечислить несколько ID через запятую; сообщения от остальных чатов игнорируются.
`TELEGRAM_MORNING_REPORT_TIME` задаёт время ежедневного отчёта по Киеву (по умолчанию `09:00`),
`LOW_STOCK_THRESHOLD` — порог малого остатка (по умолчанию 5). После изменения `.env` пересоздай API:
`docker compose up -d --build app`.

Команды: `/stats` — сводка за 7 дней, `/today` — сегодня, `/low` — низкие остатки,
`/top` — пять лидеров по количеству продаж за 30 дней, `/last` — последние пять заказов.
Бот также присылает отчёт за вчера, уведомляет о новых заказах и о снижении остатка товара до порога.
Токен не добавляй в репозиторий и не отправляй в чат.

## Публичное демо и защита действий
Для VPS за Caddy API в production Compose привязан только к `127.0.0.1:8000`; Caddy может
проксировать на этот адрес, а внешний трафик не обходит HTTPS-прокси. Перед публикацией задай
в `.env` длинный случайный `DEMO_ACTION_TOKEN` (например, создай командой
`python -c "import secrets; print(secrets.token_urlsafe(32))"`). Кнопка полной синхронизации спросит
его и хранит только в `sessionStorage` текущей вкладки. Не вставляй токен в публичный URL или frontend.

Симуляция остаётся доступной посетителям, но ограничена десятью секундами между запросами и шестью
заказами в час на IP. Лимит хранится в памяти одного процесса и сбрасывается при перезапуске приложения.
Если перед API стоит reverse proxy, укажи его IP/CIDR в `TRUSTED_PROXY_IPS`, чтобы приложение
безопасно использовало `X-Forwarded-For`; без доверенного прокси этот заголовок игнорируется.
Проверь фактический адрес/CIDR прокси на VPS перед запуском публичного compose.

## Проверки и CI
GitHub Actions запускает unit-тесты защиты и собирает Docker-образ при push и pull request.
Локально: `python -m pip install -r app/requirements-dev.txt`, затем `cd app` и `python -m pytest -q`.

## Облачное демо для портфолио (Render + Vercel + Neon)

Облачный режим использует фейковые данные в Neon и не подключается к локальному OpenCart.
Локальный Docker-сценарий остаётся с `DEMO_MODE=false`.

1. Создай бесплатную базу PostgreSQL в Neon и скопируй pooled connection string.
2. Подключи репозиторий к Render через `render.yaml`. В `DATABASE_URL` вставь строку Neon
   (секрет не добавляй в GitHub). Blueprint включает `DEMO_MODE=true`; Render сам применит миграции.
3. Один раз заполни пустую Neon-базу seed-данными локально: открой терминал в `app`, выполни
   `python seed_demo_postgres.py` и вставь строку Neon в скрытый prompt. Скрипт откажется
   запускаться, если в базе уже есть заказы или товары.
4. После создания Render-сервиса возьми его адрес `https://...onrender.com`. Скопируй
   `frontend/vercel.json.example` в `frontend/vercel.json`, замени `YOUR-RENDER-SERVICE`
   на имя сервиса и подключи в Vercel папку `frontend` как Root Directory.
5. Открой Vercel URL. Первый запрос после простоя может ждать запуск Render около минуты;
   бесплатный сервис засыпает после 15 минут без входящего трафика. Это подходит для демо,
   но Telegram-бот и ежедневные фоновые задачи на таком тарифе не работают надёжно 24/7.

В облаке симулятор создаёт заказ прямо в Neon, ограничивает сумму и число позиций, а кнопка
синхронизации OpenCart скрыта. Не добавляй токен бота, строку Neon или локальный `.env` в репозиторий.
